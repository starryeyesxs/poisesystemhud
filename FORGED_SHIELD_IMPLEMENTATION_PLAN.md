## Goal

Replace the Daedric theme's horizontal player poise bar with a Modular Forged Shield Crest while preserving the Minimalist theme's existing horizontal `#min-poise` bar.

The shield must:

- use live player poise data;
- fill from bottom to top;
- show a delayed phantom damage trail;
- show a meniscus;
- wobble and flash red on a real stagger break;
- display the existing optional numeric readout;
- inherit poise debuff and reactive hostile-effect states;
- make Cold and Fire especially prominent;
- support an independent toggle;
- support relative X/Y repositioning through the existing SKSE/INI/menu pipeline.

---

## Recommended layout

Keep the shield inside `#minimal-layout` so it inherits:

- existing left/bottom HUD anchoring;
- HUD scale;
- dynamic visibility and idle fading;
- the player cluster's lifecycle.

Recommended default placement:

- direct child of `#minimal-layout`;
- `left: calc(100% + 12px)`;
- `bottom: 0`;
- SVG width: `76px`;
- SVG height: `90px`;
- readout below the SVG;
- no fixed viewport coordinates.

With the shipped defaults, the cluster remains anchored at approximately left `20px`, bottom `30px`, with the shield placed 12px to the right of the complete cluster.

User offsets should be relative to that default:

- positive X moves right;
- positive Y moves up;
- CSS can apply:
  `translate(var(--poise-shield-x, 0px), calc(-1 * var(--poise-shield-y, 0px)))`.

Do not create a second global HUD coordinate system.

Prefer feeding the shield's trail rectangle from the existing `stat.trail` state and the existing 33ms decay loop.

- 600ms hold after damage;
- gradual release;

### 2.5 Animate the inner SVG, not the widget

### 2.6 Include the shield in idle fading

Existing idle fading targets `#minimal-bars`. Add the shield:


Active debuffs must continue to wake the HUD through `minimalState.debuffsVisible`.

### 2.7 Increase the Daedric width reserve

The current Daedric row max-width reserve is approximately `122px`. It should account for:

- 78px light crest;
- 14px layout gap;
- 12px shield gap;
- 76px shield;
- additional safety space.

Recommended reserve: approximately `222px`.

Keep the Minimalist max-width calculation unchanged.

### 2.8 Shield debuff and reactive colors

Apply classes on the shield widget using CSS variables or gradient stop colors.

Recommended mappings:

| State | Fill | Frame behavior |
|---|---|---|
| Sapped | violet-slate | subdued violet glow |
| Enfeebled / Poison | acid green | green edge/glow |
| Numbed / Cold | cyan-white to deep ice blue | strong icy glow |
| Hemorrhaging / Bleed | crimson | pulsing red edge |
| Scorched / Fire | bright ember yellow/orange/red | strong ember halo |
| Shock | brief electric blue | short shimmer |

Suggested strong colors:

- Fire:
  - top `#ffb347`
  - middle `#f05a24`
  - bottom `#7a220c`
- Cold:
  - top `#d5fbff`
  - middle `#5fd0e4`
  - bottom `#176d89`

Cold and Fire should have substantially stronger frame glows than Poison, Sapped, or Bleed.

When multiple states overlap, use a deterministic precedence:

1. Sapped
2. Poison / Enfeebled
3. Fire / Scorched
4. Cold / Numbed
5. Bleed / Hemorrhaging
6. Shock

The existing CSS already uses later-rule-wins precedence; continue that convention.

## 3. `view/minimal.js`

### 3.1 Add shield geometry constants

Near the existing HUD sizing constants:

```js
const SHIELD_CAVITY_TOP = 19;
const SHIELD_CAVITY_HEIGHT = 78;
const SHIELD_CAVITY_BOTTOM = 97;
```

### 3.2 Add a fill helper

Adapt the prototype's `setRectBounds` logic.

For a clamped percentage `p` from `0` to `1`:

- `height = 78 * p`
- `y = 19 + 78 - height`

Expected results:

- 100%: `y=19`, `height=78`
- 50%: `y=58`, `height=39`
- 0%: `y=97`, `height=0`

Use `setAttribute` and CSS transition-compatible style values.

The meniscus should:

- sit at the top of the liquid;
- disappear at effectively 0% and 100%.

### 3.3 Add shield configuration state

Add:

```js
const poiseShieldState = {
    enabled: true,
    offsetX: 0,
    offsetY: 0,
    previousPercent: 1,
    initialized: false
};
```

### 3.4 Add `configurePoiseShield`

Add:

```js
function configurePoiseShield(enabled, offsetX, offsetY) { ... }
```

It should:

1. validate a boolean and finite integer offsets;
2. validate X in `-500..2000`;
3. validate Y in `-200..2000`;
4. update `poiseShieldState`;
5. set:
   - `--poise-shield-x`
   - `--poise-shield-y`
6. call `renderMinimalStat('poise')`.

Invalid input must log an error and leave previous settings intact.

### 3.5 Extend `renderMinimalStat('poise')`

Current live poise data flows through `updateMinimalPoise()` into `minimalStat()` and `renderMinimalStat()`.

In the poise branch:

1. retain all existing horizontal row updates for Minimalist;
2. render shield fill from `stat.current`;
3. render shield trail from `stat.trail`;
4. update shield meniscus;
5. compute shield visibility from:
   - `poiseShieldState.enabled`;
   - `stat.enabled`;
   - Daedric theme;
   - existing `show` rules;
6. update the break state.

Keep a small helper such as `renderPoiseShield(stat, show)` instead of duplicating geometry logic.

### 3.6 Trigger break animation only on a real transition

Do not copy the prototype's “always animate at zero” behavior.

Trigger wobble and flash only when:

- the previous valid percentage was greater than zero;
- the new percentage is zero;
- the stat has already initialized;
- `max > 0`;
- poise remains enabled.

Do not animate when:

- the first payload arrives at zero;
- repeated polls remain zero;
- data is disabled;
- maximum is unavailable or zero.

Remove `.broken` when poise becomes positive. If needed, restart the animation with remove-class, reflow, add-class.

### 3.7 Re-render on theme changes

In `configureHudTheme()`:

- continue applying `.theme-daedric` / `.theme-minimalist`;
- render the Light Gem;
- call `renderMinimalStat('poise')`.

This guarantees an immediate representation switch without waiting for the next 100ms SKSE poll.

### 3.8 Keep the current numeric readout pipeline

`updateMinimalPoise(enabled, current, max, showNumbers)` should continue writing:

```text
current.toFixed(1) / max.toFixed(1)
```

to `#min-poise-numbers`.

The same readout now appears under the Daedric shield. No backend or provider data contract changes are required.

### 3.9 Mirror poise debuffs onto the shield

`renderPoiseDebuffIcons()` currently applies five classes to `#min-poise`:

- `debuff-sapped`
- `debuff-enfeebled`
- `debuff-numbed`
- `debuff-hemorrhaging`
- `debuff-scorched`

Retain those Minimalist classes and also toggle them on `#poise-shield-widget`.

Use the existing `ceilingRatio` to position `#poise-shield-ceiling`.

The ceiling marker should:

- run horizontally across the cavity;
- use a Y position derived from `19 + 78 * (1 - ceilingRatio)`;
- be hidden unless Enfeebled is active and the ratio is less than 1.

### 3.10 Project reactive resource effects onto the shield

Extend `renderReactiveBars()` without changing the existing Health, Magicka, or Stamina mapping.

Map current hostile states onto shield semantic classes:

| Existing effect/state | Shield class |
|---|---|
| `stamina-frost`, `debuff-numbed` | `effect-cold` |
| `health-fire`, `debuff-scorched` | `effect-fire` |
| `health-poison`, `debuff-enfeebled` | `effect-poison` |
| `health-sapped`, `debuff-sapped` | `effect-sapped` |
| `health-bleed`, `debuff-hemorrhaging` | `effect-bleed` |
| `bar-shock` | `effect-shock` |

Disabling resource bar effects should clear the shield mappings controlled by those effects, but poise-debuff colors driven by `updatePoiseDebuffs()` should remain independent.

# Edge cases

1. **Duplicate SVG IDs**
   - Reuse the existing three gradient IDs.
   - Prefix all shield-only resources.

2. **Duplicate number IDs**
   - Keep exactly one `#min-poise-numbers`.
   - Remove the dynamically generated version.

3. **Transform collision**
   - Position the widget with its transform.
   - Animate the inner SVG for wobble.

4. **Initial zero poise**
   - A first payload of zero is not a stagger event.
   - A zero maximum is unavailable data, not a break.

5. **Repeated updates at zero**
   - Do not retrigger the break animation without a positive-to-zero transition.

6. **Trail below current poise**
   - Reuse existing monotonic trail state.
   - Do not let shield rendering reverse recovery.

7. **Theme switching**
   - `configureHudTheme()` must immediately render the alternate poise display.

8. **Dynamic HUD**
   - The shield must fade with the cluster.
   - Debuffs must keep the shield visible/awake.

9. **Light Diamond**
   - The shield must not overlap `#min-emblem`.
   - Hiding the Light Diamond must not hide or reposition the shield.

10. **Minimalist isolation**
    - Existing row sizing, fill, numbers, icons, and ceiling tick must remain unchanged.

11. **Settings compatibility**
    - Missing keys retain defaults.
    - Invalid values are logged and ignored.

12. **Viewport width**
    - Increase the Daedric max-width reserve for the added shield.
    - Do not change the Minimalist width reserve.
